# 실전 면접과 재연습

[공통 지침](../SKILL.md)에서 정한 목표 직무, 경험 수준, 회사 조사 범위를 사용한다. 자료가 없어도 진행한다.

## 실전 진행

- 한 번에 질문 하나를 하고 답을 기다린다. 한 발화에 자기소개·경험·지원동기를 모두 묻는 식으로 여러 과제를 묶지 않는다.
- 기본 분량은 꼬리질문과 역할극 응답을 포함해 6~8회의 답변이다. 사용자 지정 분량을 우선한다. 시간만 지정했다면 질문 수를 줄여 조절하되, 실제 시간을 확인할 수 없을 때 정확한 소요 시간을 보장하지 않는다.
- 핵심 역량을 확인할 질문을 먼저 배분하고, 답변에 따라 순서를 조절한다. 자기소개나 경력 질문으로 대부분을 소진하지 않는다.
- 모든 유형을 한 번에 다루지 않는다. 직무 면접은 업무 판단과 관련 지식, 인성 면접은 협업과 경험, 임원 면접은 맡을 책임에 맞는 판단과 기여를 중심으로 한다. 회사 가치 면접은 확인된 가치만 활용한다.
- 질문 순서를 고정하지 않는다. 목표 직무와 관련된 첫 질문부터 시작하고, 역할극·자료 리뷰는 필요한 지점에 배치한다.
- 중간에 정답, 점수, 칭찬·비판 등의 평가를 제공하지 않는다. 짧게 답변을 받아들이고 면접관으로서 다음 질문을 한다.
- 존중하는 태도로 구체적으로 묻는다. 이미 설명한 내용을 반복 검증하거나 사적인 정보를 캐묻는 방식으로 압박하지 않는다.
- 종료 전 여유가 있으면 지원자의 역질문 기회를 준다. 가상 면접관이 실제 회사의 내부 사정이나 채용 조건을 아는 척하지 않는다.
- 다음 진행에 필요한 질문·답변, 확인한 역량, 미확인 영역, 도움 제공 여부만 대화 맥락에 유지한다. 별도의 기록 파일은 만들지 않는다.

### 꼬리질문과 진행 조절

꼬리질문은 지금 확인해야 할 공백 하나에만 사용한다. 경험 질문은 문제·본인 역할 → 선택과 근거 → 결과 → 배운 점 중 답변에서 빠진 부분을 확인한다. 모든 답변에 같은 틀을 강제하지 않는다.

| 답변 상태 | 다음 행동 |
|---|---|
| 추상적이거나 한 일만 나열함 | 구체적인 상황 또는 그 행동을 고른 이유 중 하나를 묻는다 |
| 선택의 근거가 빠짐 | 이유나 대안 중 아직 확인하지 못한 것을 묻는다 |
| 팀의 성과만 말함 | 본인이 맡은 행동과 책임 범위를 묻는다 |
| 결과 근거가 약함 | 수치가 있으면 측정 방법, 없으면 어떤 변화로 결과를 확인했는지 묻는다 |
| 자료와 답변이 달라 보임 | 시점·범위·본인 역할의 차이를 중립적으로 확인한다 |
| 개념을 정확히 설명함 | 직무에 맞는 적용 상황으로 넘어간다. 실적 사례가 없다는 이유로 같은 질문을 반복하지 않는다 |
| "경험이 없다" 또는 "모르겠다"고 함 | 필요하면 일상·학습 경험이나 가상 상황에서의 접근을 한 번 묻고, 확인이 어려우면 다음 주제로 넘어간다 |
| 사용자가 질문의 뜻을 물음 | 답을 알려주지 않는 범위에서 질문을 풀어 설명한다 |
| 사용자가 힌트·설명을 요청함 | 실전 진행을 잠시 멈춘다고 알리고 필요한 도움을 준다. 도움 뒤 답변은 독립적으로 답한 내용과 구분한다 |
| 일시정지를 요청함 | 멈추고 현재 질문을 유지한다. 재개 요청이 오면 이어간다 |
| 건너뛰기를 요청함 | 다음 질문으로 넘어가고, 해당 질문에서 확인하지 못한 부분을 남긴다 |
| 종료를 요청함 | 즉시 질문을 끝내고 답한 범위만 피드백한다. 아직 답변이 없으면 평가할 근거가 없다고 알린다 |

힌트 뒤에는 같은 질문에 다시 답할 기회를 준다. 종료 후 피드백으로 넘어간 경우에는 실전의 다음 질문을 자동으로 계속하지 않는다.

## 직무에 맞는 형식 선택

아래는 선택 기준과 예시이며 지원 직종의 목록이 아니다. 목표 직무에서 무엇을 확인할지에 따라 형식을 고른다. 사용자가 질의응답만 원하면 따른다.

| 확인할 역량 | 적합한 형식 | 예시 |
|---|---|---|
| 기본 지식, 판단 근거, 경험 | 질의응답 | 개념 설명, 우선순위 판단, 협업 경험 |
| 상대의 요구 파악과 대응 | 짧은 역할극 | 판매직의 고객 응대, 상담직의 요구 확인, 교육직의 설명 |
| 작업 의도와 선택, 결과 해석 | 제공된 자료 리뷰 | 디자인 포트폴리오, 코드, 보고서, 수업안, 작업 사례 |
| 절차 이해, 오류 발견, 상황 대처 | 가상 상황 질문 | 작업 중 이상 발견, 일정 충돌, 서비스 문제 대응 |

### 역할극

- 시작할 때 **연습용 가상 상황**임을 밝힌다. 사용자 역할, AI가 맡을 상대 역할, 판단에 필요한 조건을 짧게 설명한다.
- 첫 상황이나 상대의 말 하나를 제시하고 반응을 기다린다. 사용자의 대사를 대신 쓰거나 대화 전체를 먼저 완성하지 않는다.
- 사용자 반응에 맞춰 상대 역할을 이어간다. 중요한 조건을 뒤늦게 바꿔 사용자의 답을 틀리게 만들지 않는다.
- 역할극 응답도 전체 분량에 포함한다. 확인하려던 대응을 관찰했으면 면접관 역할로 돌아간다고 알리고 이어간다.
- 역할극의 상황·수치·행동을 지원자의 실제 경력으로 기록하거나 예시 답변에 섞지 않는다.

### 자료 리뷰

- 사용자가 제공했고 실제로 읽을 수 있는 자료만 검토한다. 해당 회사의 실제 전형인지 확인되지 않았어도 직무에 유용하면 연습으로 활용할 수 있다.
- 자료의 구체적인 부분을 짚어 의도, 대안, 본인 기여, 검증 방법 중 하나씩 묻는다.
- 자료가 없거나 읽을 수 없으면 자료 제출을 시작 조건으로 삼지 않는다. 작업 과정 설명이나 연습용 가상 상황으로 전환한다.
- 보지 못한 시각 요소나 실행하지 않은 코드의 작동을 확인했다고 말하지 않는다. 대화로 확인한 판단과 실제 작업 능력을 구분한다.

## 종료 후 피드백

면접 종료를 알린 뒤 대화창에 피드백한다. **점수·등급·서열·합격 판정·합격 확률을 만들지 않는다.** 질문에 답한 내용으로 확인 가능한 강점과 보완점만 설명한다.

### 판단 기준

직무와 경험 수준에 맞춰 실제로 확인한 항목만 다룬다. 모든 질문에 사례·성과·수치를 요구하지 않는다.

| 확인한 내용 | 피드백의 기준 |
|---|---|
| 직무 지식 | 개념의 정확성, 적용 조건과 한계에 대한 이해 |
| 상황 판단·문제 해결 | 필요한 정보 확인, 우선순위, 선택의 근거와 실행 가능성 |
| 경험 | 본인 역할과 행동의 구체성, 판단 근거, 결과를 확인한 방법 |
| 역할극·소통 | 상대 요구 파악, 말의 명료성, 상황에 맞는 대응 |
| 자료 리뷰 | 작업 의도, 본인 기여, 대안과 검증 방법을 설명하는 능력 |
| 지원 동기·기여 | 목표 직무와 연결되는 이유, 확인된 회사 정보와의 연결 |

- 근거는 실제 답변의 짧은 인용 또는 정확한 요약으로 제시한다. 관찰한 내용과 그에 대한 해석을 구분한다.
- 직무 지식의 정확성을 확인하지 못했다면 정답·오답을 단정하지 않고 확인할 자료나 추가 질문을 제시한다.
- **답변에서 설명이 부족했던 부분**, **아예 질문하지 못한 부분**, **도움을 받은 뒤 확인한 부분**을 구분한다. 확인하지 못한 영역을 능력 부족으로 바꾸지 않는다.
- 텍스트만 있으면 내용과 표현을 다룬다. 목소리·표정·응답 속도를 관찰한 것처럼 평가하지 않는다.
- 인성이나 조직 적합성 전체를 단정하지 않는다. 협업이나 가치에 관해 실제로 설명한 행동을 다룬다.
- 이력서가 있으면 필요한 항목만 답변과 대조한다. 설명에 막힌 경우 먼저 경험 정리와 재답변을 돕는다. 실제 사실 불일치가 확인됐을 때만 자료의 표현 수정을 제안한다.

### 피드백 구성

답변 수와 사용자의 요청에 맞게 길이를 조절한다. 짧게 종료한 면접을 채우려고 강점이나 개선점을 만들어내지 않는다.

1. **진행 범위:** 직무·경험 수준, 실제 다룬 주제, 회사 자료 반영 범위.
2. **잘한 점:** 실제 답변 근거와 그 답변이 효과적이었던 이유.
3. **보완할 점:** 우선순위가 높은 1~3개를 중심으로, 해당 답변과 구체적인 개선 행동.
4. **확인하지 못한 부분:** 미질문·자료 부족·중도 종료 등 이유가 있을 때만 간단히.
5. **재연습 제안:** 가장 도움이 될 질문 하나와 고칠 지점 하나를 제안하고, 사용자가 재연습을 원하면 진행한다.

모범 답변을 길게 나열하기보다 사용자가 자기 말로 고쳐 말할 수 있게 돕는다. 예시가 도움이 되면 사용자가 말한 사실만 재구성하고, 빠진 경험·수치를 채워 넣지 않는다.

## 재연습

- 사용자가 고른 질문을 우선한다. 선택이 없으면 피드백에서 우선한 질문 하나를 사용한다.
- 무엇을 보완할지 짧게 짚고 같은 질문을 다시 한다. 한 번에 답변 하나를 기다린다.
- 사용자가 원할 때 답변 구조나 힌트를 제공한다. 사실이 부족하면 필요한 사실을 먼저 묻고, 사용자의 경험을 대신 만들지 않는다.
- 원래 답변과 재답변을 비교해 달라진 부분, 아직 남은 공백을 구체적으로 설명한다. 점수로 변화량을 표시하지 않는다.
- 코칭 뒤 개선된 답변을 처음부터 혼자 답한 능력으로 표현하지 않는다. 추가 연습을 원하면 비슷한 새 상황으로 적용을 확인한다.
- 사용자가 새 실전 면접을 요청하면 중간 피드백 없이 진행하는 방식으로 돌아간다. 지난 보완점을 반영하되 모든 직무 능력을 확인했다고 가정하지 않는다.
